# DREAM PET — задача 1.9.1 «Редизайн»

Переработай текущий React/Vite-проект Dream Pet по приложенному визуальному референсу. Не переписывай приложение с нуля и не удаляй работающие механики. Работа выполняется поверх текущей архитектуры и данных.

## Главный принцип

Функциональность и маршрутизация остаются рабочими, меняется визуальная система и пользовательская подача. Результат должен выглядеть как современный премиальный маркетплейс щенков: светлый фон, молочно-белые карточки, золотисто-охристые акценты, крупная типографика, мягкие тени, скругления, спокойные анимации и много воздуха.

## Безопасность изменений и откат

1. Зафиксировать SHA текущей ветки `main`.
2. Создать резервную ветку `backup/pre-redesign-1.9.1-YYYYMMDD`.
3. Работать только в `feature/redesign-1.9.1`.
4. Не удалять старые компоненты и данные без необходимости.
5. Выполнить `npm install`, `npm run build` и проверку маршрутов GitHub Pages.
6. Не сливать изменения в `main`, если сборка или ключевые сценарии не прошли проверку.
7. Для отката закрыть PR без слияния или восстановить `main` из резервной ветки.

## Что сохранить

- React/Vite и hash-маршрутизацию для GitHub Pages.
- Главную, каталог, карточку щенка, вход, регистрацию, кабинет питомника, размещение объявления, админку и гайды.
- Фильтры по породе, городу, полу, цене и параметрам подбора.
- Краткую информацию о выбранной породе.
- CRUD объявлений питомника и модерацию в админке.
- Справочники `breeds.js`, `cities.js`, `statuses.js`, `filters.js` без дублирования.
- Обработку битых изображений.

## Вход и скрытый административный сценарий

- одна общая страница входа;
- поля email и пароль;
- обычный вход открывает кабинет питомника;
- корректная служебная пара автоматически назначает роль администратора и открывает `#/admin`;
- отдельный переключатель роли и публичную ссылку «Админка» убрать;
- пароль не хранить открытым текстом;
- для MVP допустима проверка SHA-256 на клиенте только как временная демонстрационная защита;
- для production нужна Supabase Auth/RLS или серверная проверка;
- при выходе сбрасывать роль на `visitor`.

## Адаптивность

- desktop: композиция максимально близка к референсу;
- tablet: фильтр в две колонки;
- mobile: одна колонка, раскрывающееся меню, полноширинные CTA;
- исключить горизонтальный скролл и наложение элементов.

## Критерии приёмки

- `npm run build` без ошибок;
- нет белого экрана на GitHub Pages;
- hash routes работают;
- CTA ведут в правильные сценарии;
- фильтры меняют каталог;
- карточки открываются;
- избранное переключается;
- питомник входит в кабинет;
- администратор входит только через служебную пару;
- неавторизованный пользователь не открывает кабинет и админку;
- резервная ветка позволяет мгновенно отменить редизайн.
